# Тест-кейсы User Management API

Каждая строка — проверяемое требование. Идентификаторы присутствуют в названиях
автотестов. Каждый тест и каждый DataRow получает отдельное приложение и пустое
хранилище. Тесты работают через HTTP на WebApplicationFactory/TestServer.

## Позитивные сценарии и JSON

- [x] API-01 POST: 201, JSON из пяти полей, непустой серверный GUID, DateCreated в UTC между началом и концом запроса, DateModified = null, корректный Location.
- [x] API-02 POST: код страны в нижнем/смешанном регистре сохраняется в верхнем; допустимы любые две латинские буквы без проверки справочника.
- [x] API-03 E2E: POST → GET по ID → PUT → GET; данные совпадают, ID/DateCreated сохраняются, DateModified устанавливается сервером в UTC; повторный PUT также успешен.
- [x] API-04 GET списка: 200, [] в новом приложении; после нескольких POST возвращаются все пользователи с корректной схемой и значениями.
- [x] API-05 Разные приложения изолированы: данные первого недоступны второму.

## Ошибки и отсутствие побочных эффектов

- [x] VAL-01 POST и PUT: CountryIsoCode отсутствует, null, пустой, пробельный, с цифрами/спецсимволами, длиной 1/3, нелатинский, с внешними пробелами или завершающим переводом строки → 400 с ошибкой поля.
- [x] VAL-02 POST и PUT: Locale отсутствует, null, пустой, пробельный, с цифрами/спецсимволами, неверной длиной/разделителем/регистром, нелатинский, с внешними пробелами или завершающим переводом строки → 400 с ошибкой поля.
- [x] VAL-03 POST и PUT: отсутствующее/пустое тело, null, повреждённый JSON, массив вместо объекта, неверный JSON-тип поля → 400 с понятной JSON-ошибкой.
- [x] VAL-04 POST и PUT: неизвестное свойство, UserId, DateCreated, DateModified (включая camelCase) → 400; серверные данные нельзя подменить.
- [x] VAL-05 После любого невалидного POST список пуст; после любого невалидного PUT исходная запись полностью сохранена.
- [x] ID-01 GET и PUT: неверный формат GUID и Guid.Empty → 400 с ошибкой userId.
- [x] ID-02 GET и PUT: корректный отсутствующий GUID → 404; PUT не создаёт запись.

## Пагинация

- [x] PAGE-01 Без параметров возвращается весь список, в том числе более 10 записей.
- [x] PAGE-02 page и pageSize: первая, промежуточная и последняя неполная страницы имеют ожидаемый состав; нет пропусков и повторов на неизменном наборе.
- [x] PAGE-03 Только page → pageSize=10; только pageSize → page=1.
- [x] PAGE-04 Пустое хранилище и страница за концом списка → 200 и [].
- [x] PAGE-05 Каждый параметр: 0, отрицательный, дробный, текст, пустой и больше Int32.MaxValue → 400 с ошибкой параметра.
- [x] PAGE-06 Большие допустимые page/pageSize не вызывают переполнения или 500.
- [x] PAGE-07 Стабильный порядок DateCreated, затем UserId, включая равные даты; повторный GET не меняет порядок, PUT не переставляет запись.

## Многопоточность и защита хранилища

- [x] CON-01 Параллельные POST: все запросы дают 201, все записи сохраняются, GUID уникальны, JSON корректен.
- [x] CON-02 Параллельные PUT/GET одной записи: нет ошибок; каждая прочитанная/возвращённая пара полей соответствует целому запросу, ID/DateCreated неизменны.
- [x] CON-03 Параллельные POST и GET списка: нет ошибок перечисления; каждый снимок содержит только полные записи без повторов ID.
- [x] REP-01 Репозиторий копирует входные/выходные объекты; изменение объектов извне не меняет хранилище, GetAll возвращает независимый снимок.
- [x] REP-02 Update отсутствующей записи возвращает false; GetById — null; обновление сохраняет серверные метаданные.
