# User Management API

Тестовое задание SDET C#: ASP.NET Core Web API с хранением пользователей в памяти
и автотестами на MSTest. Единственное дополнительное задание — пагинация.

## Требования и запуск

Нужен .NET SDK 10.0, стабильный выпуск. `global.json` допускает установленные
feature bands .NET 10, включая 10.0.400. При первом восстановлении нужен доступ
к NuGet. Внешняя БД и отдельный сервер для тестов не нужны.

Из корня решения:

```shell
dotnet restore
dotnet build -c Release
dotnet test -c Release
dotnet run --project UserManagement.API --no-launch-profile --urls http://localhost:5080
```

Сервис доступен по `http://localhost:5080/api/users`. При перезапуске приложения
данные теряются. Для остановки нажмите Ctrl+C.

Примеры запросов (curl; в Windows можно использовать `curl.exe`):

```shell
curl -i -X POST http://localhost:5080/api/users -H "Content-Type: application/json" -d '{"countryIsoCode":"ru","locale":"ru-RU"}'
curl http://localhost:5080/api/users
curl "http://localhost:5080/api/users?page=1&pageSize=5"
```

В следующих запросах замените `<userId>` на ID из ответа POST:

```shell
curl http://localhost:5080/api/users/<userId>
curl -i -X PUT http://localhost:5080/api/users/<userId> -H "Content-Type: application/json" -d '{"countryIsoCode":"us","locale":"en-US"}'
```

Пример тела ответа POST (201 Created):

```json
{
  "userId": "11111111-1111-1111-1111-111111111111",
  "countryIsoCode": "RU",
  "dateCreated": "2026-11-05T12:00:00Z",
  "dateModified": null,
  "locale": "ru-RU"
}
```

POST также возвращает `Location` для GET созданного пользователя. PUT возвращает
200 с изменёнными данными, сохраняя ID и дату создания; `dateModified` выставляется
сервером. Все даты — UTC. GET по ID возвращает 200, неизвестный корректный GUID
для GET/PUT — 404. DELETE в задании отсутствует.

## Валидация и ошибки

- Тело POST/PUT содержит только `countryIsoCode` и `locale`. Оба поля обязательны.
- Страна — ровно две латинские буквы в любом регистре; сохраняется в верхнем.
- Локаль — строго `xx-XX`: например, `ru-RU` или `en-US`.
- Проверяется формат, а не наличие страны/локали в справочнике.
- Пробелы не обрезаются. Неизвестные свойства JSON, включая ID и даты,
  отклоняются. Названия двух разрешённых свойств JSON регистронезависимы.
- Неправильный GUID и `Guid.Empty` возвращают 400, а не 404.
- Невалидные запросы возвращают 400 с JSON `ValidationProblemDetails`:
  `status`, `title`, `errors` с описанием ошибок. Они не меняют хранилище.

## Пагинация

`GET /api/users` всегда возвращает JSON-массив:

| Параметры | Результат |
| --- | --- |
| Нет параметров | Все пользователи, без ограничения размера |
| `page=2&pageSize=5` | Вторая страница по пять записей |
| Только `page=2` | Вторая страница, размер по умолчанию 10 |
| Только `pageSize=5` | Первая страница из пяти записей |

Нумерация начинается с 1. Оба параметра должны быть положительными целыми
числами не больше `Int32.MaxValue`; пустые значения также дают 400. Страница
за концом списка и пустое хранилище возвращают 200 и `[]`. Дополнительной
обёртки и метаданных пагинации нет.

Порядок — `DateCreated`, затем `UserId`, по возрастанию. Он сохраняется при PUT.
Разбиение выполняется по отдельному снимку хранилища; смещение считается через
`long` для защиты от переполнения. Между разными запросами страницы могут
измениться при добавлении пользователей: гарантии общего снимка нескольких
HTTP-запросов нет.

## Устройство решения и тестирование

- `UserManagement.API`: `Models`, `DTOs`, `Interfaces`, `Repositories`,
  `Controllers`. `IUserRepository` зарегистрирован как singleton.
- `UserManagement.Tests`: `Infrastructure` для фабрики/HTTP-проверок и `Tests`
  для сценариев API, валидации, пагинации, многопоточности и репозитория.
- `test-cases.md`: чек-лист требований с идентификаторами, включёнными в имена
  соответствующих тестов. Он создан до реализации сервиса.

Хранилище защищено общей блокировкой. Обновление заменяет запись целиком;
при конкурентных PUT побеждает последняя запись в хранилище. Объекты копируются
на входе и выходе, а список возвращается снимком. Чтение не раскрывает изменяемые
объекты внутри репозитория.

Каждый интеграционный тест и каждая строка `[DataRow]` получают новую
`WebApplicationFactory<Program>`, `HttpClient` и пустой репозиторий. Нет общего
статического состояния или API для сброса данных. Фабрика поднимает настоящий
конвейер ASP.NET Core в `TestServer`; HTTP-сокет и отдельно запущенный сервис
не нужны. После теста клиент и фабрика освобождаются. MSTest выполняет тесты
параллельно четырьмя workers.

Проверки включают E2E POST → GET → PUT → GET, точный состав JSON и типы данных,
валидацию POST/PUT и отсутствие побочных эффектов, GUID/404, пагинацию и
конкурентные обращения. Небольшие unit-тесты проверяют защитное копирование
репозитория. Проверки времени используют интервалы вокруг запросов без задержек.

При необходимости сохранить отчёт:

```shell
dotnet test -c Release --logger "trx;LogFileName=UserManagement.trx" --results-directory artifacts/TestResults
```

Custom middleware ошибок, интеграция логов с тестовым выводом, CI, Docker,
авторизация и постоянная БД не добавлены.
